# VELVET Recommendation Engine — Engineering Progress & Governance Ledger

This document tracks architectural decisions, non-negotiable product & CI/CD guardrails, honest technical limitations, phase-by-phase verification results, and rollback points for the VELVET Recommendation Engine project (`com.velvet.app`).

---

## 1. Non-Negotiable Product Requirement: Strict Original Studio Audio Only

**Effective for all recommendation and autoplay work (supersedes blueprint allowances for Official Music Videos / `W8_QUALITY_OMV`):**

VELVET uses YouTube Music as a discovery/source ecosystem, **not** as a music video feed. YouTube music videos must **never** appear in Autoplay or recommendation-generated queues.

### Scope of Enforcement

Applies to all recommendation-generated and queued surfaces:
- Autoplay (`AutoplayPipeline` / `checkAndExtendAutoplay`)
- Similar Songs / Related Tracks
- Song Radio
- Artist Radio
- Next Song Suggestions / Smart Shuffle injections
- Home recommendation-generated music queues & shelves

> **User Action Distinction:** A user manually selecting and playing a music video (e.g., from Videos search or an Artist's Videos tab) is an explicit user playback action and must remain independent from recommendation-generated playback filtering.

### Accept vs. Strictly Reject Policy

**ACCEPT (Verified Original Studio Music Audio Only):**
- Official Artist Topic audio releases (`- Topic` art tracks / auto-generated distributed audio).
- Verified original record-label studio audio releases (explicit audio release proof, not label video uploads).
- Verified original soundtrack audio distributed by authorized music rights holders.
- Verified original studio recording audio.

**STRICTLY REJECT:**
- Official music videos (`OMV`), **even when uploaded by verified artists or major record labels**.
- Lyrical videos and lyric videos.
- Visualizers and animated music videos.
- Fan-made videos, edits, and unofficial uploads (`UGC`).
- Live performances and concert recordings.
- Remixes, covers, mashups, slowed/reverb, sped-up, nightcore, 8D audio, and other alternate versions (unless explicitly requested as an alternate-version mode by the user).

### Fail-Closed Classification Rule (`UNVERIFIED`)

- **Verified uploader != Official Audio:** A verified artist or record label channel uploads both studio audio and official music videos. Uploader verification alone must **never** classify an upload as audio.
- **Music Search != Audio Guarantee:** Do not assume every YouTube Music search result is an audio-only release.
- **Classify Uncertain Candidates as `UNVERIFIED`:** If available metadata cannot reliably establish whether a candidate is a studio audio release or a music video, classify it as **`UNVERIFIED`** rather than automatically accepting it.
- **No Silent Relaxation:** Never weaken or bypass strict original-audio filtering simply to keep a queue full. Returning fewer tracks—or temporarily returning zero recommendations—is strictly preferable to inserting music videos.

### Honest Technical Limitations of NewPipeExtractor Metadata (`v0.26.5`)

Inspected directly in `app/src/main/java/com/velvet/app/data/YouTube.kt`, `Models.kt`, `SongIdentity.kt`, and `AutoplayPipeline.kt`:

1. **`StreamInfoItem.toSong()` Metadata Collapse (`YouTube.kt:237-259`):**
   - `YouTube.cleanArtist()` strips `" - Topic"` before constructing `Song.artist`.
   - `Song.preferredMusicSource` merges `isUploaderVerified || uploaderName.endsWith(" - Topic")` into one boolean, erasing the distinction between an auto-generated Topic art track and a verified artist/label music video channel.
2. **Missing First-Class Track Type on List Items:**
   - NewPipeExtractor `StreamInfoItem` instances returned by search, artist tabs, playlists, and kiosk charts do **not** expose YouTube Music's structured `musicVideoType` (`MUSIC_VIDEO_TYPE_ATV` vs `OMV` vs `UGC`) or `"Auto-generated by YouTube"` / `"Provided to YouTube by"` description text without separate per-item `StreamInfo.getInfo(...)` lookups or lower-level InnerTube extraction.
   - Thumbnail shape (square album artwork vs 16:9 video frame), upload channel suffix (`- Topic`), verified badge, and title heuristics alone cannot guarantee 100% classification accuracy when a label channel omits `"Official Video"` from a music video title.
3. **Current Legacy Baseline Behavior (Pre-Phase 2 Defect to Fix):**
   - `SongIdentity.classifySong()` treats `preferredMusicSource == true` as `ORIGINAL_TOPIC_AUDIO` and treats known record-label channels lacking `"video"` in the title as `RECORD_LABEL_STUDIO_AUDIO`.
   - `AutoplayPipeline.isEligible()` (`isAtv` / `isOmv`) and `Weights.W8_QUALITY_OMV` (`15.0`) currently admit Official Music Videos and give them a positive score bonus.
4. **Honesty Standard:**
   - Future phases must never claim 100% perfect classification from `StreamInfoItem` heuristics alone; instead, candidates lacking positive audio verification must resolve to `UNVERIFIED` and be excluded from recommendation-generated queues.

### Phase Allocation for Strict Original Audio Enforcement

- **Phase 1 (Current — Preserved Scope):** Zero changes to `AutoplayPipeline`, `Weights`, `SongIdentity`, or candidate filtering; telemetry cleanly separates recommendation impressions/skips/playbacks without touching queue behavior.
- **Phase 2 (Identity & Release Verification):** Preserve raw source/channel provenance fields on ingest (Topic status vs verified channel vs thumbnail/track-type evidence), introduce strict `ReleaseAudioClass` (`VERIFIED_TOPIC_AUDIO`, `VERIFIED_LABEL_STUDIO_AUDIO`, `VERIFIED_OST_AUDIO`, `REJECTED_OFFICIAL_VIDEO`, `REJECTED_LYRIC_VIDEO`, `REJECTED_VISUALIZER`, `REJECTED_LIVE`, `REJECTED_ALTERNATE_VERSION`, `REJECTED_UGC`, `UNVERIFIED`), and enforce fail-closed `isEligibleForRecommendation()` behavior.
- **Phase 3 (Candidate Generation & Hard Filtering):** Enforce strict audio-only eligibility across all recommendation candidate pools without fallback relaxation to OMVs or `UNVERIFIED` items.
- **Phase 4 (Ranking & Diversity):** Remove `W8_QUALITY_OMV` and all OMV/UNVERIFIED quality bonuses; rank strictly among verified studio audio candidates.
- **Phase 6 (Home / Next Song / Radio Integration):** Ensure `Quick picks`, `Speed Dial`, `Trending` / Home shelves, Song Radio, Artist Radio, and Smart Shuffle apply verified studio-audio filtering for recommendation-generated queues while keeping explicit user video taps independent.
- **Phase 7 (Evaluation & Regression Tests):** Add explicit automated acceptance tests proving rejection of verified-artist/verified-label Official Music Videos, lyric videos, visualizers, live recordings, alternates, and `UNVERIFIED` items, plus acceptance of Topic and verified studio audio tracks—without lowering safety gates to pad sparse queues.

## 2. Non-Negotiable CI/CD Governance Rules

Existing CI/CD infrastructure in `.github/workflows/build.yml` and `app/build.gradle.kts` must be preserved and strengthened across all phases:

1. **Preserve Workflow Structure:** Existing GitHub Actions workflow `.github/workflows/build.yml` (push/PR verification via `gradle testReleaseUnitTest assembleRelease --stacktrace`, `velvet-apk` artifact upload, tag/`workflow_dispatch`-gated `Publish Official Release`) must not be replaced, disabled, bypassed, or unnecessarily restructured. Any future CI modification must be explained and justified beforehand.
2. **Gate Before Phase Completion:** Every phase must pass relevant automated unit tests (`testReleaseUnitTest`) and Release build compilation/shrinking (`assembleRelease`) before being marked complete.
3. **Progressive Regression Suite:** Add focused unit/regression tests per phase cleanly into the existing `app:testReleaseUnitTest` runner without inflating build complexity.
4. **Honest Reporting:** Report any failing or skipped CI checks explicitly; never report a phase complete with failing required checks.
5. **Signing & Secrets Protection:** Preserve `signingConfigs.release` (`keystore/velvet.jks` fallback + `VELVET_KEYSTORE*` env vars), workflow permissions, and release asset packaging; never print credentials or tokens.
6. **Version Freeze Compliance:** Keep `versionName = "2.7.5"` unchanged unless explicitly instructed to upgrade for an actual release; internal commits do not bump release version names.
7. **Isolated & Reversible History:** Keep phase work on isolated commits/branches with documented rollback points.
8. **No Unauthorized Releases:** Never trigger tag pushes or GitHub Release publishing automatically without explicit user authorization.
9. **Continuous Ledger Updates:** Record CI run IDs, workflow changes, build status, test counts, and rollback coordinates in this file after every phase.
